# S0 原始答卷：多机器人项目的取舍与贡献呈现

〔隐私删节：本科学校及其校区、学院、政策或关联路径。〕

## 零、先给结论

你的焦虑点找错了地方。

**导师担心的从来不是"你只参与了项目的一部分"——本科生做项目本来就是团队协作，这一点所有评审都清楚。真正致命的是另外三件事：**

1. **边界模糊**：把"参与"讲成"主导"，一旦被追问到技术细节就崩，直接触发诚信质疑，这一票否决，无法挽回。
2. **重点失焦**：四个项目平均用力，每个讲一分钟，导师听完记不住任何一个。
3. **缺乏主线**：项目之间彼此孤立，看不出你是一个有方向感的人，还是一个在做任务的人。

反过来，**能清晰说出"这个系统整体是这样跑的，其中这一段是我独立设计并实现的，当时为什么这么做、踩过什么坑、现在会怎么改"的学生，即使参与范围不算最大，评价也往往高于"全包但讲不透"的人。**

所以这道题的解法不是"挑出最好的项目包装一下"，而是：**建立一套分层口径，让每个项目在你的材料里各就各位，并且每一句写在纸上的话，你都能口头复现出来。**

你现在的硬指标（〔个人成绩隐去〕、六级 〔个人成绩隐去〕）说明门槛类的问题大概率已经不是瓶颈。**推免后半程的竞争，本质是"可信度竞争"**——谁能让人相信材料上的每一句话。你的策略应该全部围绕这个展开。

## 一、第一步：给每个项目做一次"贡献体检"

不要用感觉判断"这个项目我能不能讲"，用四个硬问题来判断。找一个安静的时间，对照你的每个项目逐个回答，最好写下来：

### 问题 1｜我独立决策了什么？
不是"我参与了讨论"，而是**最终拍板由你做出的技术选择**。例如：某模块的方案对比与选型、参数整定的策略、传感器布局的决定、结构的某个设计取舍。
能列出 ≥2 个独立决策点 → 这一项过关。

### 问题 2｜我独立实现了什么？
能不能具体到：**哪几个文件 / 哪个算法文件 / 哪块 PCB / 哪段代码 / 哪份标定流程**。
标准很朴素：**如果队友的名字从项目里拿掉，你做的这部分依然完整存在且可运行。**

### 问题 3｜我能不能在没有队友在场的情况下复述全流程？
包括你没亲手做的那部分。**注意：这不要求你做过，但要求你懂。**
导师常问的一句是："这个模块不是你做的，那你说说它为什么这么设计？" 答不上来的学生，会被判定为"只知道自己那块螺丝"，而答上来的学生，会被判定为"有系统观"。这两类人的评价差距极大。

### 问题 4｜有没有客观证据？
按可信度从高到低排序：
- **最强**：论文、专利、软著、竞赛获奖证书（上面有你的名字和排序）
- **很强**：Git commit 记录（能显示你的账号在某段时间提交了什么）、你署名的设计文档 / 技术报告
- **中等**：演示视频、实物照片（能体现你所在的位置、你在操作）、调试日志截图
- **可佐证**：指导老师、队友的了解（**前提是你们事先打过招呼**）

**体检结果分类：**
| 判定 | 标准 | 处理 |
|---|---|---|
| **A 类 · 主推项目** | 四个问题全部能具体回答 | 简历主打篇幅 + 面试核心讲述对象，放 1–2 个 |
| **B 类 · 佐证项目** | 问题 1、2 能答，3、4 答得粗 | 简历用半幅篇幅，面试用于佐证技术广度，放 1–2 个 |
| **C 类 · 压缩项目** | 只能答出 1–2 个问题的某几点 | 压成一行，放"其他经历 / 竞赛与实践"栏 |
| **D 类 · 剔除项目** | 基本只剩项目名称和一个模糊印象 | 直接删掉。它在材料里是负债，不是资产 |

**一条硬性原则：宁可简历上只有三个讲得透的项目，也不要五个一碰就塌的项目。** 简历的每一条都是在向导师发出"你可以问我这个"的邀请，写上去却答不好，等于自己给自己挖坑。

## 二、取舍的优先级：四条排序规则

当你在两个项目之间犹豫时，按以下顺序裁决：

1. **能否扛住追问** ＞ 一切。
   这是唯一的否决项。答不住的项目坚决降格或删除。

2. **与目标方向的相关性** ＞ 项目名气。
   如果你申请的方向偏控制 / 运动规划，那么一个名字普通但你是核心的足式机器人步态项目，价值远高于一个名气很大但你只做了数据标注的视觉项目。
   → 这需要你先明确自己的投递方向。**同一份简历不要原封不动投所有导师。**

3. **技术纵深感** ＞ 覆盖面广度。
   一个你能讲到"为什么选择这个方法、对比过哪几个方案、最后效果提升了多少"的深度项目，胜过三个只有名词堆砌的项目。

4. **可验证产出** ＞ 主观描述。
   有实物 / 有视频 / 有指标 / 有名次的项目，永远排在有口头描述的同类之前。

**关于"参与类项目"的三条出路**（不是只有写或删两种）：

- **① 精确降格**：写成"团队项目，本人负责 XX 子模块"，保留它作为团队协作能力的证据。这在导师眼里是**加分项**——它证明你能和别人一起做成事。
- **② 换栏目**：从"科研项目"挪到"课程设计 / 竞赛实践 / 工程训练"，期待值自然降低，也就不存在"讲不清"的风险。
- **③ 仅作口述储备**：不写进简历，但如果面试被问到"你还做过什么"，拿出来讲，作为"我涉猎较广、愿意尝试"的证据。

**明确不建议的做法**：把参与类项目写成"负责人 / 主导"。推免面试的导师在自己领域里泡了十几年，一个学生真做过还是听过，三到五个追问就能分辨。虚饰一旦被识破，损失的不只是这一个项目，而是整份材料的可信度——包括你那些真实的成果也会连带被怀疑。

## 三、写法：把"经历"改写成"证据"

本科生简历最常见的问题，是写成**岗位说明书**（我负责了什么），而不是**成果说明书**（我做成了什么）。

### 核心公式

> **动作动词 + 技术对象 + 方法/约束条件 + 量化结果 + 角色标签**

逐项说明：

- **动作动词**：设计、实现、推导、搭建、标定、优化、对比、部署 —— 避免"参与""负责""协助"这类无信息量的词单独出现。
- **技术对象 + 方法**：必须写出具体技术。机器人方向的产出写作留白失效的最大原因就是通篇只有"使用了 ROS / Python / OpenCV"这种工具名词。**工具不等于技术。** 要写：`基于 Cartographer 的激光 SLAM 建图` 而不是 `使用 SLAM 技术`。
- **约束条件**：这是最能体现真实性的地方。做过工程的人一定会记得当时的限制——算力不够、传感器噪声大、场地崎岖、实时性要求。"在 XX 约束下达到 XX 效果" 这句话里，真实性密度极高。
- **量化结果**：定位精度从 X 降到 Y、响应延迟由 X ms 降至 Y ms、整机重量减轻 X%、比赛名次 X/Y 支队伍。没有精确值时用相对改进量与可复核场景，**不要编造数字**。
- **角色标签**：独立 / 核心 / 子模块负责 / 协作，必须显式写出来。这既保护你，也向导师证明你有清晰的自我认知。

### 改写对照（示例结构，请替换为你的真实内容）

**改前（典型本科生写法，问题在于全是"参与了什么"）：**
> 参与智能移动机器人项目，负责部分算法工作，使用 ROS 进行开发，完成了机器人导航功能。

这段文字传达出的信息接近零：参与了哪部分？算法是什么？导航做到什么程度？导师看完只会觉得"这个人自己也说不清"。

**改后（独立负责类 / A 类项目）：**
> **基于激光-视觉融合的室内自主导航系统 · 核心开发者（3 人团队）**
> 针对单一激光传感器在长廊环境下退化的问题，独立完成 Cartographer 与 ORB-SLAM3 的定位结果融合模块（C++/ROS2），设计基于位姿协方差自适应加权的切换策略；在 XX m × XX m 的实测场地中，将定位漂移由 X m 降至 Y m，累计运行 XX 分钟无失锁。

**改后（部分参与类 / B–C 类项目）：**
> **XX 机器人竞赛作品 · 团队成员（5 人），本人负责〔系统项目细节隐去〕抓取子模块**
> 在团队搭建的四足平台上，独立完成视觉伺服抓取子模块：实现基于深度相机的目标位姿估计与手眼标定，抓取成功率由初期约 X% 提升至 Y%；整机系统集成与步态算法由队友负责。（获 XX 奖项，排名 X/5）

第二种写法看起来"承认了不足"，实际效果更好，原因有三：**第一，它不会在追问时崩**；**第二，它显示你知道自己在一个大系统里的位置**（这叫工程素养）；**第三，它给导师一个明确、窄小、你必然答得好的提问靶心**——导师提问时会顺着你划定的边界问，而不是随机开火。

**这就是关键技巧：你不是在"暴露弱点"，你是在"引导提问"。**

## 四、面试防塌：给每个主推项目准备三层口径

写进简历只是第一步。真正决定成败的是面试那二十分钟。请为你每个 A 类项目准备三个版本，并实际开口练：

### 第一层 · 30 秒版（用于自我介绍中的项目扫读）
结构：**解决了什么问题 → 我具体做了什么 → 结果如何**
```
"这个项目要解决的是 XX 场景下 XX 的问题。我在团队里主要负责 XX 模块，
当时的主要难点是 XX，我的做法是 XX，最终把 XX 指标从 X 提升到 Y。"
```
背到能脱口而出，任何时刻被打断都能在下一句自然收住。

### 第二层 · 3 分钟版（导师说"展开讲讲"时使用）
结构：**背景 → 难点 → 方案（含取舍过程）→ 验证 → 结果 → 复盘**
要求：
- 说清楚**为什么选这个方案，放弃了什么**。这是区分"照着教程做的"和"真正想过的"的分水岭。
- 说清楚**验证方法**。怎么测的？在哪个环境下测的？测了多少次？
- **复盘必须有**：如果现在重做，我会在哪里改进。这一句的重要性被严重低估——它直接证明你具备研究者的反思习惯。

### 第三层 · 深挖层（导师开始追问时）
准备清单：
- 你用到的那个核心算法的**基本推导 / 核心公式**。讲不清公式的人，会被判定为调包侠。
- **一到两个关键参数的整定过程**：为什么取这个值？改大会怎样？改小会怎样？
- **一次具体的失败经历**：现象是什么 → 你怎么定位的 → 排除了哪些可能 → 最后怎么解决的。
  这一项请务必认真准备。**一个能讲清楚失败排查过程的学生，说服力远超过一个一路顺风讲完全程的学生。** 因为科研里大部分时间都在失败，"会排查问题"是最接近科研本质的能力。
- **这个方向的近况**：你做这件事的时候，最新的做法是什么？你现在还会怎么做？
  答不了全部可以诚实说"这块我了解不深"，但至少要能说出一两个你知道的前沿方向名词，并说明为什么没采用（成本 / 算力 / 时间）——同样是"不知道"，有无思考过程的差别巨大。

## 五、把散点项目串成一条主线

一个常见失误：简历像流水账，老师听完问"所以你到底想做什么"。

**你需要一条能串起所有项目的叙事线。** 机器人工程常见的几条线，选一条与你投递方向一致的：

- **按技术纵深**：单体算法 → 模块集成 → 系统联调 → 实机验证
- **按能力链条**：环境感知 → 决策规划 → 运动控制 → 软硬协同
- **按复杂度递进**：仿真验证 → 实物平台 → 竞赛 / 真实场景落地

用法示例（自我介绍收尾处）：
> "这几个项目我的角色从参与者逐步过渡到核心设计者，做的事从单个模块逐步扩展到整机系统的联调，也让我把方向收敛到了 XX 上。"

这段话做的事情是：**把"项目多而杂"这个表面劣势，重构为"探索过程清晰、方向逐步收敛"的成长叙事。** 这是同一批事实的两种讲法，而招生老师听到的是后者。

## 六、口径一致性：建立一张"A4 真相底稿"

这是整套方法里最容易被忽略、也最容易翻车的一环。

你的**简历、个人陈述、面试 PPT、专家推荐信、自我介绍**这些材料之间，对同一件事的表述必须完全一致。导师组是会互相核对材料的，口径不一致会被直接理解为"编造"。

建议做一张表格（不要发出去，只是给你自己用）：

| 项目名称 | 起止时间 | 团队人数 | 我的准确角色 | 我独立完成的部分 | 队友负责的部分 | 可出示的证据 | 谁能佐证 |
|---|---|---|---|---|---|---|---|
| 项目 A | 2025.03–09 | 3 | 算法核心 | 融合定位模块、实机标定 | 结构、硬件电路 | Git 记录、演示视频、竞赛二等奖 | 指导教师 X、队友 Y |
| 项目 B | 2024.11–2025.01 | 5 | 子模块负责 | 抓取位姿估计 | 平台本体、步态 | 技术报告第 3 章 | 队友 Z |
| ... | | | | | | | |

这张表的三个用途：
1. **写作保真**：写每一条之前先查表，杜绝临场"拔高"。
2. **口径统一**：不同材料从这里取同一份事实，永不错位。
3. **面试速查**：候场时花两分钟扫一遍，进门前就知道每个项目的边界在哪。

若某位老师的推荐信会提及你的某个项目，**请务必提前和老师当面或书面确认推荐信里会怎么写**，确保与你自己的表述一致。这一细节很少有人做，但它的重要性很高。

## 七、几个具体的执行提醒

1. **简历篇幅**：本科推免简历严格控制在一页 A4 之内。项目不是越多越好，**密度合适且每条都能讲五分钟**才是好简历。
2. **技术栈不要罗列太多**。写上去的每一个工具，都要准备好被问一句"你用它做过什么具体的事"。不会的工具，一个都不要写。
3. **不要在项目描述里堆砌你只听过名字的技术**。导师对这类信息的识别非常快，一个追问就足够。
4. **为不同方向准备不同的项目排序**。同一批项目，投控制方向的导师时把控制类排前面并加重写法；投视觉方向的导师时把感知类排前面。**项目总数可以减少，主推对象必须更换。** 这说明你做过功课。
5. **诚实表达不懂的部分**。被问到不会的问题时，标准答法是："这一块我没有深入做过，我的理解是 XX，如果要解决我会先看 XX 方向的资料。" —— 这远好过硬撑。绝大多数导师给学生留糊涂的空间，但不给学生留虚假的空间。
6. **六级的处理**：〔个人成绩隐去〕 是不错的分数，写清具体分值即可，不必额外修饰。英语这一项对你而言是已完成的任务，不用再投入精力。
7. **排名 〔个人成绩隐去〕 要写清楚分母和口径**。注明"专业排名 X/XXX（前 X%）"以及是加权平均还是综测排名，避免被误解。这个成绩是你的重要资产，别因为写法含糊而减分。

## 八、下一步：需要你补充的信息

以上是方法论。若要把它落到你的具体情况上，需要你补充以下三项：

1. **项目清单**：每个项目的名称、起止时间、团队人数、你的角色、使用的主要技术栈、最终产出（实物 / 视频 / 名次 / 论文 / 专利）。
2. **目标院校与导师方向**：你想投哪几位导师，各自的研究方向是什么 —— 这决定了"A 类项目"该选谁。
3. **已有成果清单**：竞赛获奖及你的排名、论文 / 专利 / 软著的署名位次。

有了这三项，可以做的事包括：帮你把每个项目归类到 A/B/C/D、逐条改写项目描述、为每个主推项目设计 30 秒 / 3 分钟两套讲稿，以及列出一份"高频追问清单"并逐个给出答法要点。

## 一句话总结

**不要用"删掉弱项目、包装强项目"的思路解题，要用"给每个项目安放正确位置"的思路。你的目标不是让所有项目看起来都很强，而是让写在纸上的每一句话，你都能在面试现场稳稳地接住三到五个追问。**

对你这个排名和这个英语水平而言，材料本身大概率已经及格了。剩下要赢的是**信任**，而信任恰恰来自诚实的边界感。

## 零、先给结论

你说的这两件事，看起来都是"不够硬"，其实**性质完全相反**：

| | 大项目里的小装置 | 尚在了解阶段的方向 |
|---|---|---|
| 本质 | **已发生的闭环资产** | **尚未兑现的方向信号** |
| 缺的不是含金量，是**独立性** | 缺的不是想法，是**证据** |
| 处理方式 | **拆出来，单列成一条完整经历** | **挪出经历栏，放进研究兴趣/未来计划** |
| 目标 | 让它替你扛住追问 | 让它不产生追问风险，同时证明方向感 |

一句话概括：**前者要"做加法"——把它的完整性写出来；后者要"做减法"——把它从"经历"降级为"意图"。**

## 一、第一类：导师大项目里的小装置 —— 拆出来单列，而且要当作主打候选

### 1.1 先纠正一个直觉错误

很多同学觉得"我只是大项目里做了一小块，写在简历上会不会显得含金量低"，于是要么不敢写，要么把它和大项目捆在一起含糊过去。**这两种处理都错了。**

真相是：**小小装置，反而是你手中最适合的主打素材。**

理由是——绝大多数本科生项目最大的软肋是**没有一个完整闭环**：干了半截、效果没验证、说不清终点在哪。而一个被明确委派的小装置，天然具备完整的链条：

> 接到一个具体指标 → 做方案对比并选型 → 出图/选型/加工/采购 → 装配调试 → 测试验证 → 得到结论或改进意见

**这条链上的每一环你都亲身走过。** 这正是导师面试时最想确认的东西：这个人能不能把一个具体问题从头做到尾。相较之下，一个名头很大但你只摸到一角的子课题，反而危险。

记住上一轮那句话：**能完整讲清楚一个小东西，远好过大而模糊地讲一个大东西。**

### 1.2 关键动作：把它与大项目"解耦"

写法的分寸全在这一点上。

**不要写成**：`参与国家 XX 项目，负责部分结构设计工作。`
——这句话有三个问题：用了"参与"这个零信息动词；"部分"这个词让人立刻想追问哪一部分；把大项目的名头借来贴在自己身上，一旦被追问到项目的其他部分，你就无处可退。

**要写成**：`依托 XX 项目中的某一子任务：某 XX 装置（导师主持课题），本人独立承担其设计与实现。`

这两种写法的差别在于：**前者你在蹭项目的光，后者你在用项目做背景。** 前者一旦追问就露馅，后者把导师的全部注意力精确引导到你胸有成竹的那一个装置上，且大项目的背景信息依然为你提供了可信度的加持。这就是上一轮说的——**不是在暴露边界，是在引导提问。**

### 1.3 推荐写法模板

```
【装置名称】
XX 项目（指导教师 XX 主持）子任务 · 本人独立负责

针对【具体需求/指标，如：XX 工况下需要实现 XX mm 定位/承受 XX N 负载/完成 XX 动作】，
完成【你的技术方案，写清具体方法而非工具名】；
期间解决了【一个具体的坑，如：装配干涉 / 传动回差 / 温漂 / 信号抖动】，
方案为【你怎么解决的】；
最终【量化结果：达到/接近/未达到指标，以及实测数据】。
```

三个必须焊死在里面的要素：

- **具体指标**。为什么难、为什么值得做，全靠这个数字撑起来。没有指标的工作在简历上等于没有工作。
- **一个具体的坑**。这是全文真实性密度最高的一句，也是你和"在网上看教程做的"之间最清晰的界线。
- **诚实的结论**。如果最后没能完全达标，**如实写"目前达到 XX，距指标差 XX，分析原因是 XX，下一步拟通过 XX 改进"**。这句话在导师眼里的分量，经常超过一个漂亮的完成结果——因为绝大多数真实工程都是这样的结局，能诚实分析差距的人，才像做科研的人。

### 1.4 关于项目名称的处理

分三种情况：

- **大项目有公开名称**（纵向课题编号、赛事命题、公开平台）→ 可以写，作为括号里的背景，不超过一行。
- **大项目是横向课题或企业合作、尚未公开** → **不要写项目名、不要写合作方、不要写具体型号**。改用功能描述："某自动化产线末端的 XX 装置""某型平台的 XX 机构"。
- **小装置本身没有正式名字** → **不要临时起一个响亮的名字**。起了名字就等于邀请导师按这个名字追问，而且一旦和答辩/Git 记录对不上会很尴尬。直接叫"XX 装置""XX 机构"即可。

### 1.5 前置动作：两个必须现在就做的确认

**这一条优先级高于所有写作技巧。** 请在动笔前依次确认：

1. **问导师能不能写、写到什么颗粒度。**
   实验室项目常存在三种限制：未结题、有保密约定、论文在投。你要当面问清三个问题：
   - 这个项目/这块内容现在可以对外讲吗？
   - 简历和面试中，我能披露到什么程度？哪些具体数据指标不能讲？
   - 如果有老师问起，我该怎么介绍我的角色？（顺便完成口径对齐）
   这一步做得漂亮，本身就是加分——它说明你有保密意识和协作常识。做得糙，可能给你的导师带来麻烦，后果比简历写得差严重得多。

2. **确认三个能否自洽的事实**：有没有图纸/加工件/测试照片/内部报告/Git 记录可以证明这是你做的？有时间跨度可以自圆其说吗？有第二个人（导师或师兄）愿意且能够在需要时为你的角色作证吗？

**如果第 1 步的答案是"暂时不能公开"，那就不要在简历上写这个项目的技术细节，改为在面试现场的自我介绍中口头提一句"在导师课题中承担过一个 XX 方向的装置设计"，得到允许的那部分。** 保住导师关系，远比多一条简历条目重要。

### 1.6 它在简历中的定位

用上一轮的四问体检重新量一遍这个小装置：如果你能说出其中的独立决策点、能指认你亲手画的图或写的代码、能讲清它在整个大系统里扮演什么角色、能拿出图纸照片或工作记录——**它就是 A 类，请直接放到"科研与实践经历"的第一条，给它最大的篇幅。**

## 二、第二类：尚在了解阶段的方向 —— 从"经历"降级为"意图"

### 2.1 先说风险

把一个还在了解阶段的项目写进"科研经历"栏，是这一轮你最可能犯的错误。它的代价是双重的：

- **它是一条你必然讲不动的条目。** 经历栏的潜台词是"你可以问我这个"，而你答不了三问以上。一旦露怯，会连累旁边那些真实条目的可信度。
- **它会消耗你最稀缺的资源——面试时间。** 二十分钟里，导师花了三分钟在一个空项目上，等于你的 A 类项目少了三分钟展示时间。这是纯粹的交易亏损。

更隐蔽的问题是"进行中"这三个字本身。**写了"进行中"，导师默认你下次见面时进度会往前走。** 若到复试、到入学前毫无进展，或者第二次被问起时还是同一套说辞，那才是最难堪的局面。

### 2.2 三条归位方案，按推荐度排序

**方案 A（推荐）：移出经历栏，放进"研究兴趣 / 未来研究计划"。**

这是它真正的位置。研究生申请完全接受甚至欢迎"还没做，但我明确想做"，**前提是你能说出为什么是它、以及它难在哪。**

写法示例：
> **研究兴趣**：〔系统项目细节隐去〕–〔系统项目细节隐去〕协同操作（空中作业方向）
> 在调研 XX 应用场景时发现，当前瓶颈集中在【具体问题：如基座扰动下的末端定位 / 机臂耦合动力学 / 实时规划算力约束】。希望围绕该问题系统学习 XX 方法，并期望在研究生阶段深入。

注意这段话里没有一个字的虚构，却完成了三件事：证明你调研过、证明你能识别问题、证明你的方向是收敛的。**这才是一个未启动项目能为你带来的真正价值——不是"我有项目"，而是"我有判断力"。**

这个写一行的难度，其实高于写一个项目。它需要你真的读过东西。**如果现在写不出"瓶颈在哪"这句话，那恰恰说明它还不到能被写进材料的时候，先去做调研，而不是先改简历。**

**方案 B：若一定要留在经历栏，必须加真实的状态标签并只写已经发生的事。**

允许的写法是"状态 + 你确实做过的动作 + 产出"：
> **〔系统项目细节隐去〕–〔系统项目细节隐去〕协同抓取 · 预研阶段（自 XX 年 XX 月起）**
> 已完成 XX 篇文献调研与 XX 开源框架的原理复现/仿真环境搭建，形成方案对比表一份；尚未进入实机验证。

这里的底线是：**每一个动词都必须对应一个真实发生的动作。** 调研了就说调研了几篇；搭了环境就说搭了什么；如果这两件事都还没做，那这条就只能走方案 A 或 C。

**方案 C：完全不写，只在面试口述中作为"下一步打算"出现。**

适用情况是：你确实还没做任何实质动作。**这是完全体面的选择**——口述比落纸轻量，风险小，且在面试官追问"你研究生阶段想做什么"时，它是最自然的答案。

### 2.3 一个时间上的建议

如果这个方向在面试前还能投入时间，**最低成本的转化是把它变成一次可陈述的小动作**：跑通一个开源仿真、复现一篇论文的核心方法、整理一份带你自己判断的文献综述。**做完这三件中的任何一件，它就有了从"研究兴趣"升级为"经历"的资格。** 在此之前，不要给它经历栏的位置。

本轮的取舍判断很简单：**有没有可陈述的事实动作，决定了它在哪个栏位；栏位不能靠意愿提升，只能靠动作提升。**

### 2.4 一个真实存在的好处

最后说句公道话：你能把"还在了解阶段"这件事主动说出来、并在简历上给它准确的位置，这件事本身经得起检验。**在材料普遍注水的环境里，一个能准确区分"我做过 / 我在做 / 我想做"的学生，是稀缺的。** 评审对疆界的敏感远超你的想象，你不需要靠虚饰取胜——你 〔个人成绩隐去〕 的排名已经替你证明了执行力，现在只需要证明判断力。

## 三、简历分区与状态词规范

### 3.1 建议的栏位结构（自上而下）

| 栏位 | 放什么 | 本轮对应内容 |
|---|---|---|
| **科研与实践经历** | 已闭环、可深挖的 A/B 类项目 | 大项目中的小装置（视体检结果） |
| **竞赛与工程实践** | 有产出、有名次、有实物的团队项目（含 C 类一行式） | 其他参与类机器人项目 |
| **研究兴趣 / 未来研究计划** | 尚未展开但有清晰判断的方向 | 〔系统项目细节隐去〕–〔系统项目细节隐去〕方向（当前推荐落位） |
| **专业技能** | 你自己用过且能被追问的工具链 | 同一原则：写上去的每一个工具都要承受追问 |

**严格一页 A4。** 栏位顺序不是固定的——如果你投递的导师方向正好是这个〔系统项目细节隐去〕方向，**可以把"研究兴趣"栏位上移并用稍多的篇幅**，因为它此时是你最重要的匹配信号。

### 3.2 状态词规范表

分寸经常败在选词上。以下是可直接套用的对照：

| 情境 | 可用表述 | 应避免 |
|---|---|---|
| 独立完成某模块 | 独立完成、承担、设计并实现 | 主持、负责（易被理解成全项目负责人） |
| 独立完成但有协作 | 核心成员，本人负责 XX | 负责人、牵头人 |
| 团队中做了一部分 | 团队成员（N 人），本人负责 XX 子模块 | 参与 XX 项目（零信息） |
| 刚起步、未验证 | 预研阶段、原理验证阶段、仿真阶段 | 正在开发 XX 系统、在研 XX 项目 |
| 只做过调研 | 完成文献调研 N 篇、完成 XX 框架复现 | 从事 XX 方向研究 |
| 依托导师课题 | 依托 XX 课题的子任务 | 参与国家级项目（暗示级别归属） |

一条通用原则：**永远用"最低调但精确"的那个词。** 导师对降级表述的第一反应是"这个人实在"，相比浮夸式包装，这是更划算的买卖。

## 四、把两件事串成一条成长线

单独看，这两段经历一强一弱；串起来看，它们恰好构成一个完整的成长叙事。你可以在自我介绍或面试收尾处这样收束：

> "我在导师的课题里完整负责过一个 XX 装置，从需求落地到实机验证全程跟下来，这段经历让我学会了怎么把一个具体的工程问题从头做到闭环。做完之后我发现自己更想处理的是系统级的耦合问题，所以最近在调研〔系统项目细节隐去〕–〔系统项目细节隐去〕协同这个方向，目前的判断是瓶颈集中在 XX。这也是我这次申请希望深入的方向。"

这段话一气呵成地做了四件事：承认小装置是你的真实产出、把它提炼为方法论、给"还在了解阶段"的新方向一个合理动机、把动机指向了你要申请的导师。**信息量和诚实度同时拉满，且全程没有一个字需要心虚。**

## 五、面试问答预案（针对本轮的两块内容）

**Q1：这个大项目很大啊，你只做了其中一小块吗？**
这是送分题。标准答法是先承认、再亮出闭环：
> "是的，项目整体由导师统筹，我负责的是其中 XX 这个装置。虽然范围不大，但完整地走了一遍 需求 → 方案 → 实现 → 验证，其中 XXX 是最难的一段，我的处理方式是……"
**注意不要心虚地补一句"项目其他部分我也了解一些"**——那会立刻把提问的焦点推到你接不住的区域。

**Q2：那你讲讲这个大项目整体是怎么做的？**
答你真实知道的：**你的装置在整个系统中处于什么位置、上下游接口是什么、它的指标为什么是那个数字。** 讲这些是加分。讲不清的部分就说"这部分主要由 XX 师兄/老师负责，我只了解接口层的约定"，这是完全可接受的。**不要试图复述你不掌握的全局。**

**Q3：〔系统项目细节隐去〕和〔系统项目细节隐去〕这个项目，现在进展到什么程度了？**（如果写在经历栏必被问）
如实回答 + 立刻转向（转向是这一题的解法）：
> "目前处于预研阶段，做的主要是调研和仿真环境搭建，还没上实机。我在调研里的判断是瓶颈在 XX，所以我想先从 XX 入手。"
**"还没上实机，但我的判断是 XX"** —— 承认了没应该做的，同时交付了一个有价值的观点。这比硬撑着说进度良好要强得多。

**Q4：你为什么选择这个新方向？**
这是最不该失分的一题，因为它本质在问你的规划能力。答法要落在**具体问题上**，而不是落在"我觉得〔系统项目细节隐去〕很酷"这类志趣取向的表达上。参考第 2.2 节方案 A 的写法。

## 六、我建议你现在就做的三件事（按紧急度）

1. **跟导师做一次范围确认**（最紧急）。问清三件事：能不能写、能写到什么颗粒度、如果被问及我的角色该怎么介绍。**这是所有其他动作的前置条件。**
2. **给小装置补完闭环资料**：图纸、照片、测试记录、当时的方案对比文档。整理这些材料的意义不只是为了写简历，更是为了在面试现场能随时调到具体的细节。
3. **给〔系统项目细节隐去〕方向安排一次最小可交付**：跑通一个相关开源仿真，或者写一份三页的调研笔记。**这会决定它在你的材料里到底值一行，还是值一个栏位。**

## 七、下一步：需要你补充的信息

若要把以上内容落到具体文字，我需要你提供：

1. **小装置**：它是什么（功能/用途）、用的什么方案、有没有实测数据或指标、达没达标、保密有无限制、时间跨度与参与人数、有无图纸/照片/Git 记录。
2. **导师大项目**：有无公开名称、大致级别（纵向/横向）、导师对你角色的表述习惯。
3. **〔系统项目细节隐去〕–〔系统项目细节隐去〕方向**：这个兴趣从何而来（课程/竞赛/文献/导师建议？）、到目前**具体做过什么动作**（哪怕只是看了几篇论文、装了某个仿真包）、你认为它的难点在哪。
4. **投递方向**：目标偏向学硕 / 专硕 / 直博，以及目标导师是否在〔系统项目细节隐去〕或〔系统项目细节隐去〕相关方向——这直接决定这个"未展开的项目"在你的材料里应该占多重的分量。
